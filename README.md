# HR Analytics: прогнозирование удовлетворённости и увольнения сотрудников

Учебный проект Data Science по HR-аналитике.

В проекте решаются две связанные задачи машинного обучения:

1. прогнозирование уровня удовлетворённости сотрудника работой;
2. прогнозирование увольнения сотрудника из компании.

Дополнительно исследуется каскадный подход: прогноз удовлетворённости из первой модели используется как дополнительный признак для модели увольнения.


## Результаты

### 1. Прогнозирование удовлетворённости

Лучшая модель - **DecisionTreeRegressor**.

| Метрика | Результат |
|---|---:|
| CV SMAPE | 15.37% |
| Test SMAPE | **14.09%** |
| DummyRegressor SMAPE | 38.26% |

Модель выполнила установленное в задаче требование: **SMAPE ≤ 15%**

Наибольший вклад в прогноз по SHAP вносят:

- оценка сотрудника руководителем (`supervisor_evaluation`);
- стаж работы (`employment_years`);
- уровень должности (`level`);
- размер заработной платы (`salary`).

---

### 2. Прогнозирование увольнения

Лучшая модель - **DecisionTreeClassifier**.

| Метрика | Результат |
|---|---:|
| CV ROC-AUC | 0.90 |
| Test ROC-AUC | **0.91** |
| DummyClassifier ROC-AUC | 0.50 |

Модель превысила установленный в задаче критерий: **ROC-AUC > 0.9**

Наибольший вклад в прогноз по SHAP вносят:

- уровень должности (`level`);
- прогнозируемый уровень удовлетворённости (`job_satisfaction_rate`);
- стаж работы (`employment_years`);
- рабочая нагрузка (`workload`).

---

## Постановка задачи

Компания располагает HR-данными о сотрудниках:

- подразделение;
- уровень должности;
- рабочая нагрузка;
- стаж;
- факт повышения за последний год;
- наличие нарушений трудового договора;
- оценка руководителя;
- заработная плата.

Для первой задачи целевая переменная - `job_satisfaction_rate`.

Для второй задачи - бинарный признак `quit`.

`id` используется только как идентификатор сотрудника и не передаётся моделям в качестве входного признака.

---

## Данные

Для первой задачи используются:

- обучающая выборка - 4000 сотрудников;
- тестовые признаки - 2000 сотрудников;
- отдельная таблица с тестовой целевой переменной.

Для второй задачи:

- обучающая выборка - 4000 сотрудников;
- те же по структуре входные признаки;
- отдельная целевая переменная `quit`;
- тестовая целевая переменная для 2000 сотрудников.

Тестовые признаки и целевые переменные сопоставляются по `id`, поскольку порядок строк в отдельных таблицах не совпадает.

Исходный датасет в репозиторий не включён. Ноутбук содержит код обработки данных, сохранённые результаты вычислений и визуализации.

## Предобработка данных

В ходе подготовки данных:

- проверены пропуски и явные дубликаты;
- проверена уникальность `id`;
- исправлена опечатка `sinior - senior`;
- строки, состоящие только из пробелов, приведены к пропущенным значениям;
- категориальные признаки разделены на номинальные и порядковые;
- обработка пропусков и кодирование признаков выполняются внутри `Pipeline` / `ColumnTransformer`.

Для номинальных признаков используется One-Hot Encoding.

Для порядковых признаков задан естественный порядок:

- `junior < middle < senior`;
- `low < medium < high`.

Числовые признаки масштабируются внутри пайплайна для моделей, которым это необходимо.


## Исследовательский анализ

### Удовлетворённость сотрудников

Сотрудники представлены пятью подразделениями. Среди уровней должности преобладают `junior` и `middle`, наиболее распространён средний уровень рабочей нагрузки.

Стаж сотрудников составляет от 1 до 10 лет. Медианная зарплата - около 30 000.

Целевая переменная `job_satisfaction_rate` принимает значения от 0.03 до 1.00, медиана составляет 0.56.

Для анализа взаимосвязей признаков использовалась матрица Phi_K.

Наиболее выраженная связь уровня удовлетворённости наблюдается с оценкой руководителя; также обнаружены связи с другими характеристиками сотрудников.


### Увольнение сотрудников

Около **28%** сотрудников в обучающей выборке покинули компанию.

Для анализа использовалась не только структура группы ушедших сотрудников, но и **доля увольнений внутри каждой категории**.

В данной выборке повышенная частота увольнений наблюдается:

- среди `junior`-специалистов;
- среди сотрудников с небольшим стажем, особенно около одного года;
- при низкой рабочей нагрузке;
- среди сотрудников, не получавших повышения за последний год;
- среди сотрудников с нарушениями трудового договора;
- при более низких оценках руководителя.

Доля увольнений по подразделениям различается заметно меньше: примерно от 25% до 30%.

Сотрудники, покинувшие компанию, также в среднем имеют более низкую зарплату.

Эти результаты описывают статистические связи в выборке и не интерпретируются как доказанные причинно-следственные зависимости.

## Feature engineering

Для второй задачи был создан дополнительный признак: `job_satisfaction_rate` Он представляет собой **прогноз уровня удовлетворённости**, полученный лучшей моделью первой задачи.

Перед созданием признака проверено пересечение обучающих выборок двух задач по `id`: **общих сотрудников не обнаружено.**

Поэтому модель первой задачи формирует прогноз удовлетворённости для сотрудников второй задачи, которых она не использовала при обучении. Это снижает риск утечки информации при построении каскада из двух моделей.


## Модели

### Задача 1 - регрессия

Сравнивались:

- `LinearRegression`;
- `DecisionTreeRegressor`.

Подбор гиперпараметров выполнялся с помощью `RandomizedSearchCV` и 5-кратной кросс-валидации.

Основная метрика - **SMAPE**.

Лучший результат показал `DecisionTreeRegressor`.


### Задача 2 - классификация

Сравнивались:

- `LogisticRegression`;
- `KNeighborsClassifier`;
- `DecisionTreeClassifier`.

Подбор гиперпараметров также выполнялся с помощью `RandomizedSearchCV` и 5-кратной кросс-валидации.

Основная метрика - **ROC-AUC**. ROC-AUC использован для оценки способности модели ранжировать сотрудников по вероятности положительного класса при неравномерном распределении классов.

Лучший результат показал `DecisionTreeClassifier`.


## Интерпретация моделей

Для оценки вклада признаков использовались **SHAP values**.

В первой задаче наиболее важными для прогнозов модели оказались:

- `supervisor_evaluation`;
- `employment_years`;
- `level`;
- `salary`.

Во второй задаче:

- `level`;
- `job_satisfaction_rate`;
- `employment_years`;
- `workload`.

SHAP используется для интерпретации поведения обученных моделей и не рассматривается как доказательство причинного влияния признаков на удовлетворённость или увольнение сотрудников.

## Основные выводы

В проекте построены две связанные модели машинного обучения.

**DecisionTreeRegressor** прогнозирует уровень удовлетворённости с **Test SMAPE = 14.09%** и значительно превосходит константный baseline.

**DecisionTreeClassifier** прогнозирует увольнение сотрудников с **Test ROC-AUC = 0.91** при baseline ROC-AUC = 0.50.

Обе модели выполнили заданные критерии качества на отложенных тестовых данных.

Дополнительный признак `job_satisfaction_rate` оказался среди наиболее важных признаков второй модели, что показывает потенциальную полезность каскадного подхода.

При этом найденные взаимосвязи являются статистическими: результаты проекта не позволяют утверждать, что изменение конкретного признака само по себе вызовет изменение удовлетворённости или вероятности увольнения.


## Возможное практическое применение

Модели могут использоваться как дополнительный аналитический инструмент для:

- выявления групп сотрудников с повышенным прогнозируемым риском ухода;
- приоритизации дальнейшего HR-анализа;
- формирования гипотез о причинах различий между группами сотрудников;
- анализа удовлетворённости как одного из потенциально полезных сигналов для задачи удержания персонала.

Прогноз модели не следует использовать как автоматическое основание для кадровых решений.

Перед практическим применением необходимо дополнительно проверить:

- качество моделей на новых данных;
- стабильность метрик во времени;
- качество прогнозов для различных групп сотрудников;
- изменение распределений признаков;
- влияние предполагаемых HR-мер на реальные бизнес-метрики.

Фактическое снижение текучести кадров или финансовых потерь в рамках данного offline-проекта не измерялось.


## Возможные направления развития

- сравнить качество модели увольнения с `job_satisfaction_rate` и без него при одинаковой схеме кросс-валидации;
- провести анализ ошибок классификации;
- дополнительно оценить Precision, Recall и PR-AUC при выборе рабочего порога;
- проверить временную стабильность модели при наличии данных за несколько периодов;
- исследовать качество модели отдельно для различных групп сотрудников.
